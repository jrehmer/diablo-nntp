- `dexpireover` and `doverctl clean` with `readergrouphash hierarchy` or `hierarchy-full`: the overview files at the top of the group home are now expired, rewritten (`-R`), compressed (`-z`) and cleaned like those in its subdirectories. The hierarchy layouts put there the files of a group of one component (`junk`, `control`) and, with plain `hierarchy`, of a group of two components whose first has one character (`x.y`: `o.0.x.y`, `d.<n>.x.y`), and both tools only entered the directories: these groups were never expired, their data files never removed, the files of such a group removed from the active file never cleaned, and GROUP kept reporting the old first article (`211 12 1 12` after articles 1-4 expired, now `211 8 5 12`). At the top the tools act only on regular files (the scan follows, opens and removes no symlink there; a group whose over file there is a link is not expired, as before) with the over and data file names of groups whose directory is the top, and on the temporary files `dexpireover` leaves for groups in the active file. What is removed there: the stale data files of existing groups; the temporary files of an interrupted `-R` or `-z` of existing groups; the over file of a group no longer in the active file when its header names that group, and, once that removal worked, that group's data files in the same run (`-n` reports them as well). What stays: every other name (an admin's files, the file names of groups that live in a subdirectory), an over file whose header does not name the group of its name, a data file of no group unless the same run removed that group's over file (so the data files of a removed group whose over file was already gone stay and must be removed by hand), and after a switch between `hierarchy` and `hierarchy-full` the old files at the top, which are left alone as in subdirectories. With plain `hierarchy` a group of one character `x` shares the top with `x.gz` (`d.<n>.x.gz` is the plain data of the one and the compressed name of the other): `dexpireover -R` rewrites neither of them there, `-z` does not compress `x`'s data, and the file is kept while either group needs it. `dexpireover -R` now leaves a group as it is, in any directory, when one of the data file names of its range is there but no regular file: a FIFO there made it hang (also before D-338), and at the top also a link (below the top `-R` still reads through a link to a regular file and replaces the link by a regular file, as before); `-v` says "<group>: not rewritten: <path> is not a regular file". The data files of a group whose over file at the top is no regular file are left as they are. A switch from `hierarchy` to `hierarchy-full` keeps x.gz's old files at the top, and `-R` of x then leaves them too. `dexpireover` now reports an over or data file of no group it cannot remove ("Unable to remove <path>: <error>"), as `doverctl clean` does. With `dexpireover -p N` one worker does the top. crc and md5 spools are not affected (D-338).
