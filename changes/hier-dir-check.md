- `dexpireover` and `doverctl clean` with `readergrouphash hierarchy` or `hierarchy-full`: a file is the file of a group only in that group's directory, and a file in the group's directory of the other hierarchy layout is left alone. The file name holds the whole group name, but the two layouts put many groups in different directories (`e2e.x.gz` in `e2e/` or `e2e/x/`, `a.b.c` in `a.b/` or `a/b/`), and the file's directory was not compared. After a switch between `hierarchy` and `hierarchy-full` made by editing `readergrouphash` (`doverctl convert` refuses it), the copies in the old directories were taken as the groups' files: `dexpireover` expired them with the group's own files, which moved the group's first article past its last, emptied OVER of the group and removed old data files as stale. Now the old-directory copies are neither expired nor removed (`-v`: "left alone"), as a dreaderd started before the change may still write them, and `dexpireover` does not move the first article number of such a group; they stay until they are removed by hand with the server stopped. The data name `d.<n>.X.gz` (the plain data of a group X.gz, or the compressed data of X) is judged by the group whose directory it is in: with `hierarchy-full`, and with `hierarchy` for groups like `e2e.foo` and `e2e.foo.gz` (in `e2e/` and `e2e/foo/`), the data files of a removed X.gz are no longer kept as X's, and a stale file in X's directory is removed even when X.gz has articles in that base. Where X and X.gz share a directory (`hierarchy`, `e2e.x` and `e2e.x.gz` in `e2e/`) nothing changes; crc and md5 spools are not affected (D-336, D-337).
