- `doverctl clean -o` (new option): removes the over and data files that the groups of the active file have in their directory of the other hierarchy layout, the leftovers of a switch between `readergrouphash hierarchy` and `hierarchy-full` made by editing `diablo.config` (`doverctl convert` refuses this conversion). The two layouts put many groups in different directories (`e2e.x.gz`: `e2e/` or `e2e/x/`; `a.b.c`: `a.b/` or `a/b/`; `x.y`: the top of the group home or `x/`), and `dexpireover` and `doverctl clean` leave the files in a group's old directory alone, as a dreaderd started before the change may still write them; `dexpireover` also does not move the first article number of such a group while its over file is there, so GROUP kept counting articles only the old files held. With `-o` each such file is removed ("Removing file of <group> in the directory of the other hierarchy layout: <path>", also with `-n`, which removes nothing); then `dexpireover` moves the first article number again (`211 12 1 12` became `211 6 7 12` after a switch with 6 articles before and 6 after it). Not removed: the files of the configured layout, files of groups not in the active file (clean treats them as before), and with plain `hierarchy` the data name `d.<n>.X.gz` that a group `X.gz` shares with the compressed data of `X` in the same directory (it is judged by both groups, D-318, D-325). With `-w` only the files of the matching groups are removed, and a shared `d.<n>.X.gz` of a group `X.gz` that `-w` leaves out stays as without `-o`. At the top of the group home only regular files are looked at, as before. `doverctl clean -o` refuses, with exit status 1 and before touching anything, while dreaderd may run (its pid file `dreaderd.pid` in `path_log` names a live process, or holds no pid, or its control socket `dreader_socket` accepts a connection), and when `readergrouphash` is not `hierarchy` or `hierarchy-full`. dreaderd must stay stopped for the whole run: the check is no lock, so it is made again before each removal, and a dreaderd started during the run stops `clean -o` with exit status 1, the files not yet removed left in place. The check cannot see a dreaderd on another host sharing the spool or one started with another `diablo.config`. The removed files are the overview of the old layout: after `clean -o` a switch back leaves OVER of every moved group empty, so run it only when you will not switch back. `clean` no longer takes an option after it (`clean -o`) as its directory argument, which it never used: `doverctl clean -n` was a real clean, it is now a dry run. A letter that takes no value (`-m`, `-n`, `-o`, `-V`) followed by more characters is refused (exit 1) instead of read as that letter alone (`-on` was `-o` without `-n`), and so is a value of `-v` or `-d` that is not a number (`-vo` was `-v0`) (D-337).
