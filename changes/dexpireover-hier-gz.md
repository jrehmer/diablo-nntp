- dexpireover: with the hierarchy layout (`readergrouphash hierarchy`) `dexpireover -a` no longer removes the compressed data file `d.<n>.<group>.gz` of a live group whose name contains `.d.` (such as `e2e.d.q`) as "Group for over file not found": a hierarchy `.gz` data name is the compressed data of group `X` or the plain data of group `X.gz`, and both groups are looked up, as `doverctl clean` does since D-318: the file is removed only when it is stale for every group that exists. Over and data files are now told apart by parsing the name, not by `.o.` and `.d.` in it: the over file of a group like `e2e.d.q` is no longer taken for a stale data file as well (and removed once the group's first article is 256 or more), and the data files of a group like `e2e.o.x` are no longer read as over files ("bad file header"). Behaviour change: `dexpireover` now checks every hierarchy data file `d.<n>.<group>` for staleness (outside the group's range, misaligned, or of no group), as it does for the crc and md5 layouts and as `doverctl clean` does, and `-z` also compresses the plain ones, except that a plain data file of a group whose last component is one character (such as `e2e.x`) is not compressed in the hierarchy layout, because the compressed name `d.<n>.e2e.x.gz` is also the data file name of the group `e2e.x.gz` (D-325). With `-w` a `.gz` data file whose other group is not selected is left alone. The data entries per file of a group are read from its over file by its path from the group home, so a hierarchy group with a dexpire.ctl `e` other than 256 keeps its live data files (before, the count fell back to 256 and `dexpireover -a` removed live files that were not on a multiple of 256, or the file with the oldest articles with `e1024`).
