- doverctl: `clean` no longer removes the compressed data files (`d.<n>.<group>.gz`, made by `dexpireover -z`) of the hierarchy layout (`readergrouphash hierarchy`). The `.gz` suffix was taken into the group name, so every compressed data file looked like the file of a group that does not exist (D-318). A group name may itself end in `.gz`, and `d.<n>.<name>.gz` is then the plain data file of that group or the compressed data of the group without the suffix: `clean` keeps the file as long as either group exists. `dexpireover -a` still has this fault for groups whose name contains `.d.` (it scans no other hierarchy data names).
