- doverctl clean: it scanned only group directories whose first two characters are alphanumeric, so it never cleaned `md5-32\1` (one-character directories) or a hierarchy group whose first component is one character (`a.bcd.efg` lives in `a.bcd/`). It now enters the directories the configured `readergrouphash` can have made (D-326), and no longer enters `lost+found`, whose files it used to remove as unknown. A symlink in the group home is still followed when its name starts with two alphanumerics, as before; a symlink of any other name is skipped (`-v` says so). After a followed symlink, clean now goes back to the group home instead of the parent of the link's target, and no longer removes the link or, once it is empty, the link's target. dexpireover also scans the `+` and `-` directories of `md5-64\N`, which it skipped, so groups whose hash starts with those characters are expired again; a symlink of such a name is skipped (`-v` says so), not followed. Below a directory that the old rules did not enter (those new names in clean, `+` and `-` in dexpireover), neither tool follows a symlink to a directory (`-v` says so); the directories they entered before still follow links, as before.
