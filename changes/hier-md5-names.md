- `dexpireover` and `doverctl clean` no longer remove the overview of a group whose name starts like `o.<n>.<n>` or `d.<n>.<n>` (for example `o.1.2`) with `readergrouphash hierarchy` or `hierarchy-full`: its over and data file names (`o.0.o.1.2`, `d.0.o.1.2`) were read as md5 file names first, of a group that does not exist, and removed as "Group for over file not found". The file name parse now tries the names of the configured layout first; `dexpireover` also removes the `-R` temporary files of such groups now. When a group `o` or `d` existed, the same files were taken as that group's: `doverctl clean` removed them ("bad file header - removing", "Deleting stale overview data o") and `dexpireover` removed the data files ("Deleting stale overview data for o"); that is fixed too. crc and md5 spools are not affected (D-335).
