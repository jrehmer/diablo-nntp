- `dexpireover -R` with `readergrouphash hierarchy` no longer destroys the overview data of a group `X.gz` when it rewrites the group `X` (D-325). With plain `hierarchy` a group whose last component has one character (`e2e.x`, `o.1.2`, `comp.lang.c`) and the group of the same name plus `.gz` have their files in one directory (`e2e/`, `o.1/`, `comp/lang/`), and `d.<n>.X.gz` is the compressed data name of the one and the plain data file of the other: the rewrite of `X` removed it as `X`'s old compressed data, so OVER of `X.gz` was empty afterwards, and the rewrite of `X.gz` read it as its own data although it may be `X`'s. Now `-R` rewrites neither group of such a pair in any directory (before, only at the top of the group home), and `-v` says "<group>: not rewritten: the group <other> has its files in the same directory (D-325)" (at the top with ", the top of the group home" as before). The same holds after a switch from `hierarchy` to `hierarchy-full` made by editing `readergrouphash`: `X` stays in its directory, `X.gz` moves to a directory of its own (`e2e/x/`), and while `X.gz`'s old over file is still in `X`'s directory `-R` leaves `X` as it is, so `X.gz`'s old files survive and a switch back finds them. Only pairs whose other group is in the active file count, also with `-w`, which loads only the selected groups. A spool that was always `hierarchy-full` rewrites both groups as before (their files are in different directories). Expiry without `-R`, `-z` (which already left `X`'s data plain there) and `doverctl` are unchanged, so with plain `hierarchy` the data files of such a pair are now never rewritten or compressed; `doverctl convert` between the two layouts is still refused (D-325 stays open for it).
